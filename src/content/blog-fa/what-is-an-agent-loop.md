دور و بر «ایجنت‌ها» هاله‌ای از رمز و راز شکل گرفته است. فریمورک‌ها گراف‌های ارکستریشن، ماشین‌های حالت و انتزاع‌هایی با اسم‌هایی مثل `AgentExecutor` می‌فروشند. راحت می‌شود به این نتیجه رسید که ایجنت چیز پیچیده‌ای است.

نیست. حلقهٔ ایجنت حدوداً چهل خط کد است، و وقتی یک بار خودتان آن را بنویسید، هر فریمورکی برایتان خوانا می‌شود.

## فرق چت‌بات و ایجنت

چت‌بات جواب می‌دهد. ایجنت **عمل می‌کند، نتیجه را بررسی می‌کند، و دوباره عمل می‌کند**.

کل تفاوت همین است. چت‌بات یک درخواست است و یک پاسخ. ایجنت حلقه‌ای است که تا تمام شدن کار ادامه می‌دهد — ابزارها را صدا می‌زند، خروجی برگشتی را می‌خواند، و تصمیم می‌گیرد قدم بعدی چه باشد.

## تبادل پیام

همه‌چیز روی یک تبادل ساده بنا شده است:

1. چند ابزار را برای مدل توصیف می‌کنید.
2. مدل با یک **درخواست ساخت‌یافته** برای استفاده از یکی از آن‌ها جواب می‌دهد — یک نام و آرگومان‌ها.
3. شما تابع واقعی را اجرا می‌کنید.
4. نتیجه را به مدل برمی‌گردانید.
5. مدل یا ابزار دیگری را صدا می‌زند یا جواب نهایی را می‌دهد.

گام ۵ همان حلقه است. همین.

## حلقه در Python

```python
MAX_STEPS = 10

def run_turn(context):
    for _ in range(MAX_STEPS):
        r = client.responses.create(model=MODEL, input=context, tools=TOOLS)

        # The model's output IS the memory — feed it back in.
        context += r.output

        # Stop rule: no tool call means the agent is done.
        if not any(i.type == "function_call" for i in r.output):
            return r.output_text

        for item in r.output:
            if item.type != "function_call":
                continue
            args = json.loads(item.arguments)
            result = TOOL_FNS[item.name](**args)
            context.append({
                "type": "function_call_output",
                "call_id": item.call_id,
                "output": result,
            })

    return "Stopped: hit the step limit."
```

## همان حلقه در TypeScript

```ts
const MAX_STEPS = 10;

export async function runTurn(context: OpenAI.Responses.ResponseInput): Promise<string> {
  for (let step = 0; step < MAX_STEPS; step++) {
    const r = await client.responses.create({ model: MODEL, input: context, tools: TOOLS });

    context.push(...(r.output as OpenAI.Responses.ResponseInputItem[]));

    if (!r.output.some((i) => i.type === "function_call")) return r.output_text;

    for (const item of r.output) {
      if (item.type !== "function_call") continue;
      const args = JSON.parse(item.arguments);
      const result = await TOOL_FNS[item.name](args);
      context.push({ type: "function_call_output", call_id: item.call_id, output: result });
    }
  }
  return "Stopped: hit the step limit.";
}
```

## چهار تصمیمی که واقعاً مهم‌اند

کد کوتاه است. مهندسیِ کار در چهار انتخابی است که این کد در دل خودش دارد.

### ۱. لیست مکالمه همان حافظه است

هیچ حافظه‌ای روی سرور وجود ندارد. مدل دقیقاً همان چیزی را می‌داند که در `input` گذاشته‌اید و نه چیزی بیشتر. این که خروجی خود مدل را دوباره به همان لیست اضافه می‌کنید همان چیزی است که نوبت بعدی را منسجم نگه می‌دارد — و فراموش کردنش رایج‌ترین باگ ایجنت‌هاست.

### ۲. قاعدهٔ توقف

*تول‌کال نبودن یعنی کار ایجنت تمام شده است.* همین یک خط است که «ایجنتی که کار را تمام می‌کند» را از «ایجنتی که تا ابد در حلقه از خودش سؤال می‌پرسد» جدا می‌کند. این قاعده‌ای است که خودتان انتخاب می‌کنید، نه خاصیتی از مدل.

### ۳. سقف تعداد گام‌ها

ایجنتِ بدون سقف گام یعنی صورتحسابی بی‌انتها و یک حلقهٔ بی‌نهایتِ بالقوه. ده گام پیش‌فرض معقولی است. اینکه وقتی به سقف رسیدید چه کنید — با صدای بلند شکست بخورید، از کاربر بپرسید، پیشرفت را خلاصه کنید — یک تصمیم محصولی است.

### ۴. خطاها داده‌اند، نه اکسپشن

وقتی ابزاری شکست می‌خورد، کرش نکنید. متن خطا را مثل یک نتیجهٔ عادیِ ابزار به مدل برگردانید. یک مدل توانمند `<tool_error>No such file: confg.json</tool_error>` را می‌خواند و با `config.json` دوباره تلاش می‌کند. اگر به‌جایش اکسپشن پرتاب کنید، یک خوداصلاحیِ مجانی را دور انداخته‌اید.

## چرا خودتان بنویسیدش

فریمورک‌ها دقیقاً همین حلقه را پنهان می‌کنند، و این یعنی وقتی ایجنت‌تان بدرفتاری می‌کند، به‌جای جریان کنترل خودتان دارید انتزاعِ یک نفر دیگر را دیباگ می‌کنید.

وقتی خودتان حلقه را نوشته باشید:

- **حلقه‌های افسارگسیخته** بدیهی می‌شوند — می‌دانید شمارندهٔ گام‌ها کجا زندگی می‌کند.
- **باد کردن کانتکست** بدیهی می‌شود — دقیقاً می‌دانید هر نوبت چه چیزی به لیست اضافه می‌شود.
- **انتخاب اشتباه ابزار** آشکارا یک مشکلِ توضیحِ ابزار است، نه یک معما.
- **فریمورک‌ها خوانا می‌شوند.** می‌توانید به هر کتابخانهٔ ایجنتی نگاه کنید و آن را به همین چهل خط برگردانید.

نکتهٔ آخر استدلال اصلی است. این حرف ضدفریمورک نیست — حرف این است که فریمورکی را که شکلش را نمی‌فهمید نمی‌توانید ارزیابی کنید.

## بعدش چه؟

حلقه بنیان کار است، اما حلقه به‌تنهایی محصول نیست. دور آن به ابزارهایی نیاز دارید که ارزش صدا زدن داشته باشند، ارزیابی‌هایی که ثابت کنند کار می‌کند، مدیریت کانتکست تا مکالمه‌های طولانی مقرون‌به‌صرفه بمانند، و تأیید انسانی پیش از هر کار برگشت‌ناپذیر.

هر کدام از این‌ها یک زیرسیستم واقعی است. اما همه‌شان از همین چهل خط بالا آویزان‌اند.
