وقتی یک بار [حلقهٔ ایجنت را با دست نوشته باشید](/blog/what-is-an-agent-loop)، فریمورک‌ها دیگر ترسناک نیستند و *خوانا* می‌شوند. می‌توانید به هر کدامشان نگاه کنید و تنها سؤالی را بپرسید که اهمیت دارد: **این فریمورک کدام بخش از حلقه را برای من انجام می‌دهد، و آیا اصلاً در آن بخش به کمک نیاز داشتم؟**

پس بیایید دقیقاً همین کار را با **Agents SDK** اوپن‌ای‌آی بکنیم — فریمورک رسمی‌ای که روی [Responses API](/blog/chat-completions-vs-responses-api) سوار است. نه یک فهرست قابلیت‌ها، بلکه یک نقشه: به‌ازای هر قطعه‌ای که به شما می‌دهد، مسئلهٔ دست‌سازی که جایگزینش می‌شود.

## نسخهٔ یک‌جمله‌ای

Responses API به شما *یک پاسخ مدل* می‌دهد. Agents SDK به شما *یک اجرای ایجنت* می‌دهد.

کل تفاوت همین است. با API خام، **خودتان** حلقه را اجرا می‌کنید: پیام‌ها را می‌فرستید، تول‌کال‌ها را می‌خوانید، اجرایشان می‌کنید، نتایج را اضافه می‌کنید، دوباره می‌فرستید و تصمیم می‌گیرید کی متوقف شوید. رانرِ SDK این حلقه را برایتان اجرا می‌کند — «حلقهٔ ابزار را انجام می‌دهد، بعد از هندآف‌ها ایجنت را عوض می‌کند، و وقتی اجرا تمام شود یا برای تأیید متوقف شود، می‌ایستد.» هر چیز دیگری در SDK یک انتزاع خوش‌انتخاب است که به همین رانر آویزان شده.

اگر کنترل مستقیم روی مسیریابی و منطق حلقهٔ سفارشی می‌خواهید، روی Responses API می‌مانید. اگر می‌خواهید SDK مالک ارکستریشن باشد، یک سطح بالاتر می‌روید. در هر دو حالت، فراخوانی‌های زیرین مدل یکسان‌اند.

## تعریف یک ایجنت

شیء اصلی `Agent` است: یک نام، دستورالعمل‌ها (سیستم‌پرامپتش)، یک مدل و مجموعه‌ای از ابزارها. این هم در هر دو زبان، مستقیم از مستندات:

```python
from agents import Agent, function_tool

@function_tool
def get_weather(city: str) -> str:
    """Return the weather for a given city."""
    return f"The weather in {city} is sunny."

agent = Agent(
    name="Weather bot",
    instructions="You are a helpful weather bot.",
    model="gpt-5.6",
    tools=[get_weather],
)
```

```typescript
import { Agent, tool } from "@openai/agents";
import { z } from "zod";

const getWeather = tool({
  name: "get_weather",
  description: "Return the weather for a given city.",
  parameters: z.object({ city: z.string() }),
  async execute({ city }) {
    return `The weather in ${city} is sunny.`;
  },
});

const agent = new Agent({
  name: "Weather bot",
  instructions: "You are a helpful weather bot.",
  model: "gpt-5.6",
  tools: [getWeather],
});
```

دقت کنید «ابزار» در اینجا چیست: **یک تابع معمولی به‌علاوهٔ یک اسکیما**. در پایتون، دکوریتور `@function_tool` تایپ‌هینت‌ها و داک‌استرینگ شما را می‌خواند تا JSON اسکیمایی را بسازد که مدل می‌بیند. در تایپ‌اسکریپت یک اسکیمای [Zod](https://zod.dev) و یک تابع `execute` به آن می‌دهید. این دقیقاً همان چیزی است که در غیر این صورت با دست می‌نوشتید — یک نام، یک توضیح، یک اسکیمای پارامترها و کدی که اجرا می‌شود — فقط بویلرپلیتش برایتان تولید شده. اگر قبلاً [برای یک ایجنت ابزار طراحی کرده باشید](/curriculum/week-5-tools-that-touch-code)، هیچ چیز اینجا تازه نیست؛ همان قرارداد است، با تایپ کمتر.

## اجرای آن — حلقه‌ای که مجبور نشدید بنویسید

```python
from agents import Runner

result = await Runner.run(agent, "What's the weather in Kyoto?")
print(result.final_output)
```

```typescript
import { run } from "@openai/agents";

const result = await run(agent, "What's the weather in Kyoto?");
console.log(result.finalOutput);
```

همین یک فراخوانی `run`، همان حلقهٔ چهل‌خطی است. زیر پوسته: مدل را صدا می‌زند، درخواستِ فراخوانی `get_weather` را می‌بیند، تابع شما را اجرا می‌کند، نتیجه را برمی‌گرداند به مدل، دوباره مدل را صدا می‌زند و وقتی مدل به‌جای یک تول‌کال دیگر، پاسخ نهایی تولید کرد، برمی‌گردد. قانون توقف، دیسپچ ابزار، اضافه‌کردن پیام‌ها — همه‌اش — داخل `Runner.run` است.

**خروجی ساخت‌یافته** یک گزینهٔ درجه‌یک است: به ایجنت یک `output_type` (یک مدل Pydantic) یا `outputType` (یک اسکیمای Zod) بدهید و اجرا به‌جای متن آزاد، دادهٔ تایپ‌دار و اعتبارسنجی‌شده برمی‌گرداند:

```python
from pydantic import BaseModel
from agents import Agent, Runner

class CalendarEvent(BaseModel):
    name: str
    date: str
    participants: list[str]

agent = Agent(
    name="Calendar extractor",
    instructions="Extract calendar events from text.",
    output_type=CalendarEvent,
)

result = await Runner.run(agent, "Dinner with Priya and Sam on Friday.")
print(result.final_output)  # a CalendarEvent, not a string
```

## هندآف‌ها: چند-ایجنتی بدون روتری که خودتان نگه دارید

این قابلیتِ امضای SDK است و روشن‌ترین دلیل برای سراغش رفتن. یک **هندآف** به یک ایجنت اجازه می‌دهد ادامهٔ اجرا را به ایجنت متخصص دیگری واگذار کند — و رانر «بعد از هندآف‌ها ایجنت را عوض می‌کند»، به‌صورت خودکار.

الگوی رایج، یک ایجنت *تریاژ* است که تمام کارش تصمیم‌گیری دربارهٔ این است که چه کسی باید درخواست را رسیدگی کند:

```python
triage_agent = Agent(
    name="Triage",
    instructions="Route the user to the right specialist.",
    handoffs=[billing_agent, refunds_agent, support_agent],
)
```

این را مقایسه کنید با اینکه خودتان انجامش دهید: یک فراخوانی مدل برای دسته‌بندی نیت اجرا می‌کردید، روی نتیجه `switch` می‌زدید و حلقهٔ دومی را با سیستم‌پرامپت و مجموعه‌ابزار متفاوت شروع می‌کردید — سیم‌کشی‌ای که خودتان می‌نویسید، تست می‌کنید و نگه می‌دارید. هندآف‌ها واگذاری را به یک **پریمیتیو توکار با مالکیت شفاف** تبدیل می‌کنند: هر ایجنتی که اجرا به او واگذار شود، حالا مالک مکالمه است، با همهٔ ابزارهایش. این ستون فقرات [ارکستریشن چند-ایجنتی](/curriculum/week-12-multi-agent-orchestration) است — یک ایجنت مدیر با متخصص‌ها، جایی که حتی می‌توان یک ایجنت را *به‌عنوان یک ابزار* در اختیار ایجنت دیگری گذاشت.

## گاردریل‌ها: بررسی‌هایی که می‌توانند اجرا را متوقف کنند

**گاردریل‌ها** بررسی‌هایی در سطح ورودی، خروجی و ابزار هستند که «پیش از ادامهٔ کارِ پرریسک، مسدود یا متوقف می‌کنند.» یک گاردریل ورودی می‌تواند درخواست خارج از موضوع یا ناامن را قبل از اینکه اصلاً فراخوانی گران‌قیمت مدل اتفاق بیفتد رد کند؛ یک گاردریل ابزار می‌تواند **پیش از اجرای یک اقدام خطرناک، تأیید** بخواهد — و چون اجراها قابل ازسرگیری‌اند، ایجنت متوقف می‌شود، یک انسان تأیید می‌کند و از همان‌جا که مانده بود ادامه می‌دهد.

با دست، این می‌شود یک کپه `if` پخش‌شده دور حلقه‌تان و یک سازوکار سفارشی برای سریالایز کردن وضعیت، در حالی که منتظر یک انسان هستید. SDK آن را به یک لایهٔ اعلانی با اجرای قابل ازسرگیریِ توکار تبدیل می‌کند — چیزی که همان لحظه‌ای اهمیت پیدا می‌کند که یک ابزار بتواند پول خرج کند یا به پروداکشن دست بزند.

## سشن‌ها، وضعیت، و مسئلهٔ حافظه

SDK برای وضعیت مکالمه «همان گزینه‌های Responses API» را به شما می‌دهد — تاریخچهٔ دستی، زنجیره‌کردن پاسخ‌ها، Conversations API — **به‌علاوهٔ سشن‌های SDK و وضعیت اجرای قابل ازسرگیری**. به زبان ساده: می‌توانید بگذارید SDK مکالمهٔ در جریان را در طول نوبت‌ها برایتان دنبال کند، به‌جای اینکه خودتان فهرست تاریخچه را در هر فراخوانی رد کنید. این پاسخ فریمورک به لوله‌کشی [حافظه و سشن](/curriculum/week-9-memory-and-sessions) است که هر ایجنت واقعی بالاخره به آن نیاز پیدا می‌کند.

## تریسینگ: بخشی که ساعت ۲ بامداد قدرش را می‌دانید

هر اجرا تریس می‌شود — «تریس‌های توکار در سراسر فراخوانی‌های مدل، ابزارها، ایجنت‌ها، گاردریل‌ها و هندآف‌ها.» وقتی یک اجرای چند-ایجنتی کار گیج‌کننده‌ای می‌کند، به‌جای زل زدن به لاگ‌های خام درخواست‌ها، یک خط زمانی ساخت‌یافته دارید از اینکه *کدام ایجنت فعال بود، چه چیزی را صدا زد، چه چیزی برگشت و کجا هندآف کرد*. ساختن این چیز به‌شکل خوب، واقعاً سخت است، و همین قابلیتی است که وقتی وسط دِیباگ عصبی ارکستریشن هستید، بی‌سروصدا هزینهٔ کل این انتزاع را جبران می‌کند.

## پس باید ازش استفاده کنید؟

این چارچوب صادقانه‌ای است که دوره در پیش می‌گیرد. **اول حلقه را با دست بنویسید** — چهل خط است و هر فریمورکی را خوانا می‌کند، از جمله همین یکی. بعد وقتی مسئله‌تان واقعاً همان شکلی را دارد که SDK برایش ساخته شده، سراغش بروید:

- **سراغش بروید** وقتی ارکستریشن چند-ایجنتی واقعی دارید (هندآف‌های واقعی، نه یک دسته‌بند)، وقتی به دروازه‌های تأیید روی ابزارهای پرریسک نیاز دارید، یا وقتی تریسینگ بین متخصص‌ها ارزش این وابستگی را دارد.
- **روی Responses API خام بمانید** وقتی کنترل کامل مسیریابی و یک حلقهٔ سفارشی می‌خواهید، یا وقتی «ایجنت» شما در واقع یک مدل با سه ابزار است — که در این صورت SDK تشریفاتی است که به آن نیازی ندارید.

SDK نه جادوست و نه عصا. مجموعه‌ای از پیش‌فرض‌های معقول است برای دقیقاً همان مشکلاتی که *بعد از* کار افتادن حلقه به آن‌ها برمی‌خورید. دانستن اینکه هر قطعه جایگزین چه چیزی می‌شود، همان چیزی است که به شما اجازه می‌دهد آگاهانه انتخابش کنید، نه اینکه چون README چشمگیر به‌نظر می‌رسید، کورکورانه از یک فریمورک تقلید کنید.
