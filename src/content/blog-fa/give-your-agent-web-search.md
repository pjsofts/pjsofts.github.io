هر مدلی یک نقطهٔ قطع آموزشی دارد. درباره‌ٔ نسخه‌ای از یک فریمورک که ماه پیش شیپ شده، آخرین دور جذب سرمایهٔ یک شرکت، یا یادداشت‌های انتشار دیروز از او بپرسید، و یکی از این دو کار را می‌کند: اعتراف می‌کند که نمی‌داند، یا — بدتر — با اعتمادبه‌نفس پاسخی می‌سازد که درست به نظر می‌رسد.

جست‌وجوی وب راه بستن این شکاف است. و در ۲۰۲۶ دیگر خودتان آن را نمی‌سازید. نه اسکریپر، نه پارس‌کردن HTML، نه رولت محدودیت نرخ. یک **ابزار** به مدل می‌دهید، مدل تصمیم می‌گیرد کِی صدایش کند، و یک ارائه‌دهندهٔ جست‌وجو نتایج تمیز و آمادهٔ ارجاع برمی‌گرداند.

اینکه واقعاً چطور کار می‌کند، دو مسیر سیم‌کشی‌اش، و نحوهٔ انتخاب بینشان در ادامه آمده است.

## مدل ذهنی: جست‌وجو ابزاری است که مدل ماشه‌اش را می‌کشد

شما یک جست‌وجو اجرا نمی‌کنید که نتایجش را در پرامپت بچسبانید. آن نسخهٔ ساده‌لوحانه است، و در هر نوبت توکن می‌سوزاند، چه سؤال به اطلاعات تازه نیاز داشته باشد چه نه.

در عوض یک **ابزار جست‌وجوی وب** ثبت می‌کنید و می‌گذارید مدل ماشه را بکشد. برای یک سؤال بی‌نیاز — «این رشته را برعکس کن» — هرگز جست‌وجو نمی‌کند. برای «نسخهٔ پایدار فعلی AI SDK چیست؟» ابزار را صدا می‌زند، نتایج را می‌خواند، و از روی آن‌ها پاسخ می‌دهد. این همان الگوی درلحظهٔ هر تول‌کال دیگری است: زمان‌بندی مالِ مدل است، سیاست‌گذاری مالِ شما.

با یک گیت‌وی جلوی مدل‌هایتان، کل ماجرا چند خط است. همهٔ آنچه در ادامه می‌آید از پارامتر `tools` در AI SDK استفاده می‌کند — ابزار در همان درخواستی سوار می‌شود که پرامپت.

## مسیر ۱: جست‌وجوی مستقل از ارائه‌دهنده (با هر مدلی کار می‌کند)

منعطف‌ترین گزینه، ابزار جست‌وجویی است که به سازندهٔ مدل گره نخورده است. هر مدلی را — OpenAI، Anthropic، Google، هرچه — از یک بک‌اند جست‌وجوی یکسان عبور دهید. سه‌تایشان ارزش شناختن دارند: **Perplexity**، **Exa** و **Parallel**.

`gateway` را ایمپورت می‌کنید و ابزار را داخل `tools` می‌اندازید. این هم جست‌وجوی Perplexity با `streamText`:

```typescript
import { gateway, streamText } from 'ai';

export async function POST(request: Request) {
  const { prompt } = await request.json();

  const result = streamText({
    model: 'openai/gpt-5.5', // works with ANY model, not just Perplexity
    prompt,
    tools: {
      perplexity_search: gateway.tools.perplexitySearch(),
    },
  });

  return result.toUIMessageStreamResponse();
}
```

کل یکپارچه‌سازی همین است. مدل ابزاری به نام `perplexity_search` می‌بیند، تصمیم می‌گیرد کِی به اطلاعات به‌روز نیاز دارد، و گیت‌وی فراخوانی را به API جست‌وجو هدایت می‌کند. شما هرگز مستقیم به اندپوینت جست‌وجو دست نمی‌زنید.

هر ارائه‌دهنده شخصیتی دارد که ارزش دارد با مورد استفاده‌تان جورش کنید:

- **Perplexity** — همه‌منظوره و همه‌فن‌حریف. پیش‌فرض خوبی است. از فیلترهای تازگی (`day`/`week`/`month`/`year`)، فهرست‌های مجاز/ممنوع دامنه، و نتایج به تفکیک کشور پشتیبانی می‌کند.
- **Exa** — ساخته‌شده برای ایجنت‌ها. در فیلتر دامنه و تاریخ، هدف‌گیری دسته (`news`، `research paper`، `company`) و گزیده‌های توکن‌صرفه‌جو که با دقت کنترلشان می‌کنید قوی است.
- **Parallel** — گزیده‌های بهینه‌شده برای LLM با یک حالت `agentic` که نتایج فشرده و کم‌توکن مخصوص گردش‌کارهای چندمرحله‌ای برمی‌گرداند.

و هرکدامشان را می‌توانید مقید کنید. این هم Exa محدود به اخبارِ سه رسانه، فقط ۲۴ ساعت اخیر، پنج نتیجه:

```typescript
import { gateway, generateText } from 'ai';

const { text } = await generateText({
  model: 'openai/gpt-5.5',
  prompt,
  tools: {
    exa_search: gateway.tools.exaSearch({
      type: 'fast',
      numResults: 5,
      category: 'news',
      includeDomains: ['reuters.com', 'bbc.com', 'nytimes.com'],
      contents: { highlights: true, maxAgeHours: 24 },
    }),
  },
});
```

**سراغ این مسیر بروید وقتی** رفتار جست‌وجوی *یکسانی* بین مدل‌های مختلف می‌خواهید، یا وقتی مدلی استفاده می‌کنید که ارائه‌دهنده‌اش اصلاً جست‌وجوی بومی ندارد. یک ابزار، نتایج یکدست، تعویض آزادانهٔ مدل.

## مسیر ۲: جست‌وجوی بومیِ ارائه‌دهنده

حالا هر ارائه‌دهندهٔ بزرگی ابزار جست‌وجوی وب خودش را عرضه می‌کند، تنظیم‌شده برای مدل خودش. این‌ها برای همان ارائه‌دهنده بهینه شده‌اند و اغلب امکانات اضافه‌ای هم دارند. سیم‌کشی تقریباً یکسان است — به‌جای `gateway` پکیج ارائه‌دهنده را ایمپورت می‌کنید.

**Anthropic** (Claude)، با کنترل دامنه و نشانه‌های مکانی:

```typescript
import { streamText } from 'ai';
import { anthropic } from '@ai-sdk/anthropic';

const result = streamText({
  model: 'anthropic/claude-opus-4.8',
  prompt,
  tools: {
    web_search: anthropic.tools.webSearch_20250305({
      maxUses: 3,
      allowedDomains: ['techcrunch.com', 'wired.com'],
      blockedDomains: ['example-spam-site.com'],
      userLocation: {
        type: 'approximate',
        country: 'US',
        region: 'California',
        city: 'San Francisco',
        timezone: 'America/Los_Angeles',
      },
    }),
  },
});
```

**OpenAI** مختصرگوی جمع است — برای شروع هیچ پیکربندی‌ای لازم ندارد:

```typescript
import { streamText } from 'ai';
import { openai } from '@ai-sdk/openai';

const result = streamText({
  model: 'openai/gpt-5.5',
  prompt,
  tools: {
    web_search: openai.tools.webSearch({}),
  },
});
```

**Google** مدل Gemini را به Google Search زمین‌گیر (ground) می‌کند (`vertex.tools.googleSearch({})` روی Vertex، یا `google.tools.googleSearch({})` روی AI Studio — به‌علاوهٔ یک نسخهٔ سازمانی با نگهداری صفر داده). **xAI** به Grok ابزار `xai.tools.webSearch({})` را می‌دهد، و تنها موردی است که با `enableImageUnderstanding: true` می‌تواند تصاویر را هم جست‌وجو *و درک* کند.

**سراغ این مسیر بروید وقتی** به یک ارائه‌دهنده متعهدید و جست‌وجوی تنظیم‌شده‌اش یا قابلیتی را می‌خواهید که ابزارهای عمومی ندارند — بودجهٔ جست‌وجوی به‌ازای هر مکالمه در Claude، درک تصویر در xAI، زمین‌گیرکردن در Google.

## پس‌گرفتن منابع (بخشی که اهمیت دارد همین است)

پاسخ حاصل از جست‌وجوی وب بدون ارجاع، یک ریسک است. اگر مدل چیزی به کاربرتان می‌گوید، می‌خواهید نشان دهید *از کجا آمده* — هم برای اعتماد و هم برای دیباگ خودتان وقتی چیزی را اشتباه می‌گوید.

ابزارهای بومی، متادیتای منابع — عنوان‌ها و URLها — را از طریق یک رویداد اختصاصی `source` در استریم برمی‌گردانند. وقتی روی استریم کامل پیمایش می‌کنید، کنار متن مراقبش باشید:

```typescript
for await (const part of result.fullStream) {
  if (part.type === 'text-delta') {
    process.stdout.write(part.text);
  } else if (part.type === 'source') {
    // { title, url } — render these as citations under the answer
    console.log('source:', part.source.title, part.source.url);
  }
}
```

این‌ها را به‌صورت پانویس یا چیپ‌های درون‌متنی نمایش دهید. پاسخی با سه منبع لینک‌شده مثل *پژوهش* خوانده می‌شود؛ همان پاسخ بدون هیچ منبعی مثل *یک حدس*.

## چقدر خرج دارد (و آن ردیف هزینه‌ای که از قلم می‌افتد)

جست‌وجوی وب **جدا از توکن‌ها** محاسبه می‌شود، و قیمت‌گذاری به‌ازای هر درخواست است، نه هر توکن:

- **Perplexity** — حدود \$5 به‌ازای هر ۱٬۰۰۰ جست‌وجو.
- **Exa** — حدود \$7 به‌ازای هر ۱٬۰۰۰ جست‌وجو (هرکدام تا ۱۰ نتیجه؛ نتایج اضافه جداگانه محاسبه می‌شود).
- **Parallel** — حدود \$5 به‌ازای هر ۱٬۰۰۰ جست‌وجو (این هم با ۱۰ نتیجهٔ شامل‌شده).
- **بومیِ ارائه‌دهنده** — قیمت به تفکیک مدل؛ نرخ جست‌وجوی وبِ ارائه‌دهنده را چک کنید.

این هم ردیفی که مردم فراموش می‌کنند: هزینهٔ جست‌وجو فقط نصف صورتحساب است. هر نتیجه‌ای که مدل می‌خواند، در گام بعدی به **توکن ورودی** تبدیل می‌شود. جست‌وجویی که پنج صفحه گزیده وارد کانتکست می‌کند، به‌راحتی می‌تواند در توکن‌ها بیشتر از هزینهٔ جست‌وجو خرج بردارد. پیچ‌های `maxResults`، `maxTokens` و طول گزیده دقیقاً برای همین وجود دارند — جزئیات وسواسی نیستند، ولوم هزینهٔ شما هستند. عامدانه تنظیمشان کنید.

## چطور انتخاب کنیم، در سه خط

- **در حال نمونه‌سازی هستید یا مدام مدل عوض می‌کنید؟** مستقل از ارائه‌دهنده (Perplexity/Exa/Parallel). یک ابزار، هر مدلی.
- **به یک ارائه‌دهنده قفل شده‌اید و بهترینِ او را می‌خواهید؟** ابزار بومی. نتایج تنظیم‌شده، قابلیت‌های اضافه.
- **در هر دو حالت:** نتایج را سقف بگذارید، منابع را همیشه نمایش دهید، و توکن‌های بازیابی‌شده را جزئی از هزینه حساب کنید.

## تصویر بزرگ‌تر

جست‌وجوی وب همان بازیابیِ درلحظه است — خواهر و برادرِ وبِ بازِ RAG. آن‌یکی از پیکرهٔ خصوصی *شما* بازیابی می‌کند؛ جست‌وجوی وب از وب عمومی. شکل ماجرا یکی است: مدل تشخیص می‌دهد به یک واقعیت نیاز دارد، ابزاری را صدا می‌زند، آنچه برمی‌گردد را می‌خواند، و به‌جای اتکا به خاطرهٔ تارِ داده‌های آموزشی، بر پایهٔ آن استدلال می‌کند.

وقتی از این زاویه ببینیدش، «جست‌وجوی وب را اضافه کن» دیگر یک قابلیت نیست و یک تصمیم طراحی می‌شود: *این ایجنت به کدام دانش نیاز دارد، و آن دانش کجا زندگی می‌کند؟* بخشی‌اش در دیتابیس شماست (RAG). بخشی‌اش روی وب است (جست‌وجو). بخشی‌اش در همین درخواست فعلی است (کانتکست). انتخاب منبع درست برای هر واقعیت، بخش عمدهٔ آن چیزی است که مهندسی کانتکست واقعاً هست.
